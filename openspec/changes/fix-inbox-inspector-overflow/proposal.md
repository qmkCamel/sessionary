# Change: 修复工作区内容横向溢出

## 背景

Inbox 在桌面窗口中使用 master-detail 布局。当前详情面板和长 session 标题在部分窗口宽度下会撑出页面，造成全局横向滚动条，并让右侧详情内容被裁切。
同类风险也存在于紧凑侧栏品牌文字和运营复盘表格：在窗口宽度收紧时，固定列宽或未收敛的长文本会产生不必要的横向滚动。

## 目标

- Inbox 页面不得因为右侧 detail inspector 或长文本产生全局横向滚动。
- 长 session summary、项目路径、PR URL、命令和文件名必须在详情面板内换行或省略，不能撑开面板。
- 详情面板在宽屏保持可用的 master-detail 结构，在较窄桌面宽度回退为单列布局。
- Today、Timeline、Operating Review、Report、Settings 不得产生全局横向滚动。
- 运营复盘桌面宽度下的表格应优先收敛列宽或改为单列区域，而不是出现不必要的内部横向滚动。
- 左侧导航在长页面纵向滚动时必须保持顶部品牌、日期和主导航可见。
- Settings 页面必须以清晰分组呈现语言、数据来源、项目根目录、集成和备份/恢复，开关控件不得贴边或使用失控尺寸。
- 项目根目录为空时必须给出每行一个目录的输入示例。
- Settings 不得为了布局修复继续保留 release readiness、本地打包检查或等价的项目专用打包检查区域。
- Report 页面必须避免报告编辑器与页面外层形成双重纵向滚动。

## 不做

- 不调整 session 数据模型或扫描逻辑。
- 不改变状态标记、review、repair、delivery 等用户动作语义。
- 不新增远程请求或改变 local-first 数据边界。

## 成功标准

- 1440px 窗口下 Inbox 不出现全局横向滚动条。
- 1100px-1365px 窗口下 Inbox 不保留永久右栏。
- 详情面板内部长文本不会撑出容器。
- 主页面在 1440px、1365px、1100px、760px 宽度下不出现全局横向滚动。
- Report 等长页面滚动后，左侧栏不得被页面内容带走或裁掉顶部入口。
- Settings 页面来源配置和集成配置在桌面为卡片分组，在窄屏回退单列，启用开关保持稳定尺寸。
- 项目根目录为空时显示示例 placeholder。
- 原“发布准备”/“本地打包检查”不再作为 Settings 产品区域展示。
- Report 编辑器随内容自然增高，页面保留单一主滚动，右侧摘要在宽屏下 sticky。
