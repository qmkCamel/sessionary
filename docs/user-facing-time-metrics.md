# Sessionary 面向用户的时间统计说明

日期：2026-05-25

## 一句话

Sessionary 的时间统计不是工时表，而是一张 AI 协作账本。它帮助用户看清楚：一天里有多少注意力花在下指令、等待 AI、检查结果和修复返工上。

不要把这些数字理解成“我今天工作了多久”。更准确的理解是：

```text
我今天和 AI 协作时，注意力花在哪里？
```

## 用户应该怎么看

| 指标 | 用户理解 | 当前来源 | 精确度 |
| --- | --- | --- | --- |
| 指令时间 | 我为了让 AI 明白任务而投入的表达、整理和补上下文时间 | 默认估算；用户可手动修正 | 趋势可用，不是精确输入耗时 |
| AI 等待时间 | AI 在运行、我理论上可以切去做别的事的时间 | session 总时长减去指令时间 | 粗略可用，不是模型真实运行时长 |
| 复盘时间 | 我检查 AI 产物是否可用的时间 | 默认估算；使用 Start Review / Done 后为真实计时 | 计时器记录时较准确 |
| 修复时间 | 我为了让 AI 产物变可用而补救的时间 | 默认 0；用户标记或计时后记录 | 取决于用户是否记录 |
| 并行时间 | 多个 session 或项目在同一段真实时钟时间里同时运行 | 根据 session 起止时间重叠计算 | 适合看并行工作流，不按并发数翻倍 |

## 最重要的边界

### 1. 指令时间当前不是精确打字时间

当前默认估算：

```text
指令时间 = min(用户消息数 * 90 秒, session 总时长 * 35%)
```

它表达的是“这次 session 大概花了多少指令准备成本”，不是用户真的在输入框里打字了多久。

这个估算适合回答：

- 今天是不是频繁补指令？
- 某个 session 是不是沟通成本偏高？
- 哪些任务更需要提前整理需求？

它不适合回答：

- 我具体打字打了几分钟？
- 我在别的编辑器里准备 prompt 花了多久？
- 每一条 prompt 的真实写作时间是多少？

### 2. 输入框计时更准确，但只覆盖输入框内发生的事

如果未来 Sessionary 能提供自己的 prompt composer，或者能接入工具侧输入事件，可以记录：

```text
first_input_at -> send_at
```

这样能得到更准确的“输入框编辑时间”。

但这仍然不是完整的“指令准备时间”。用户可能在 VS Code、备忘录、文档或脑子里先想好，再粘贴进输入框发送。那时输入框只看到 2 秒，真实准备可能是 20 分钟。

因此面向用户更稳妥的来源标签应是：

| 来源标签 | 含义 |
| --- | --- |
| 估算 | 只能从外部工具日志看到发送后的消息，因此按消息数和 session 时长估算 |
| 手动 | 用户在 Detail 里手动修正过 |
| 计时 | 用户使用 Start Review / Start Repair 等计时器记录 |
| 输入框记录 | 未来如果 Sessionary 自己记录输入框编辑过程，可用该标签 |

### 3. AI 等待时间不是浪费时间

AI 等待时间表示 AI 在跑、用户可以去做别的事的窗口。它是否浪费，取决于有没有被复用：

- 如果等待时用户在 review 另一个 session，说明等待被回收了。
- 如果等待时没有其他活动，它更像空等。
- 如果等待后产生大量修复时间，说明这次等待不一定换来了可用产出。

## 推荐 UI 文案

### Today 总览

```text
人工投入：1h 28m
包含指令、复盘和修复。部分来自估算，部分来自你的手动记录。
```

```text
AI 等待：2h 10m
表示 AI 运行时你可以切走的时间，不等于浪费时间。
```

```text
并行时间：37m
表示至少两个 session 或项目在同一段真实时钟时间里同时运行。10 分钟同时跑 3 个 session，仍记 10 分钟。
```

### Session Detail

```text
指令时间：6m
来源：估算
```

```text
复盘时间：12m
来源：计时
```

```text
修复时间：20m
来源：手动
```

### 报告说明

```text
这些时间用于复盘 AI 协作方式，不用于精确工时、绩效评价或代码归因。
```

## 典型例子

### 例子 1：一句话交给 AI，长时间等待

用户做了什么：

```text
用户发 1 条指令，让 AI 重构一个组件。
AI 跑了 30 分钟。
用户没有手动记录 review / repair。
```

当前估算：

```text
指令时间 = min(1 * 90 秒, 30 分钟 * 35%) = 1 分 30 秒
AI 等待时间 = 30 分钟 - 1 分 30 秒 = 28 分 30 秒
复盘时间 = 30 分钟 * 12%，但限制在 1 到 15 分钟之间，约 3 分 36 秒
修复时间 = 0
```

用户应该怎么理解：

```text
这不是一个沟通成本高的 session。
主要时间都在 AI 等待上。
下一步要看等待期间是否做了别的事，以及产出是否被吸收。
```

### 例子 2：短 session 里多轮纠偏

用户做了什么：

```text
session 总共 12 分钟。
用户连续发了 6 条消息：改这里、再跑测试、再修一下、继续。
```

当前估算：

```text
按消息数估算 = 6 * 90 秒 = 9 分钟
35% 上限 = 12 分钟 * 35% = 4 分 12 秒
最终指令时间 = 4 分 12 秒
AI 等待时间 = 7 分 48 秒
```

用户应该怎么理解：

```text
这类 session 可能不是 AI 跑得慢，而是任务在过程中被频繁修正。
指令时间被上限压住，是为了避免把短 session 中很多短消息夸大成超长输入时间。
```

产品可以提示：

```text
这次 session 的指令往返较多。下次可以先把验收标准和边界写清楚。
```

### 例子 3：用户在别处写好长 prompt，再粘贴发送

用户做了什么：

```text
用户在 VS Code 里花 20 分钟写 prompt。
复制到 Codex / Claude 输入框。
2 秒后发送。
session 总时长 40 分钟，用户消息数 1。
```

当前估算：

```text
指令时间 = min(90 秒, 40 分钟 * 35%) = 1 分 30 秒
```

真实情况：

```text
用户真实准备指令约 20 分钟。
Sessionary 从外部日志只能看到已经发送的消息，看不到发送前在 VS Code 里的准备过程。
```

用户应该怎么理解：

```text
这里的指令时间会明显低估。
如果用户关心这类任务的真实投入，应手动修正指令时间。
```

产品可以提示：

```text
如果这条指令是在其他地方提前写好的，可以手动修正指令时间。
```

### 例子 4：等待被复用，AI 并行带来收益

用户做了什么：

```text
项目 A 的 AI session 从 10:00 跑到 10:30。
用户在 10:10 开始复盘项目 B 的另一个 session，复盘到 10:25。
```

统计结果：

```text
项目 A 有 30 分钟 active time。
其中 15 分钟 AI 等待与项目 B 的复盘重叠。
aiWaitingHumanOverlap = 15 分钟
```

用户应该怎么理解：

```text
这 15 分钟不是空等。
用户把 AI 等待时间用来处理另一个结果，因此并行工作流产生了实际收益。
```

产品可以提示：

```text
你把 15 分钟 AI 等待用于复盘其他 session，等待时间被有效回收。
```

### 例子 5：等待很多，但最后修复也很多

用户做了什么：

```text
AI 跑了 45 分钟。
用户复盘发现不能直接用。
之后又花 25 分钟修复。
```

统计结果：

```text
AI 等待时间高。
修复时间也高。
```

用户应该怎么理解：

```text
这不是简单的“AI 帮我省了 45 分钟”。
更准确地说：AI 产生了一段很长的自动运行时间，但交付质量不足，后续返工成本较高。
```

产品可以提示：

```text
这次 session 的等待时间较长，且修复成本偏高。下次可以先缩小任务范围，或要求 AI 分阶段提交可检查结果。
```

### 例子 6：并行时间不会按 session 数翻倍

用户做了什么：

```text
10:00 到 10:10，同时有 3 个 session 在运行。
```

统计结果：

```text
并行时间 = 10 分钟
不是 30 分钟。
```

用户应该怎么理解：

```text
并行时间按真实时钟计算。
它回答的是“有多少真实时间处于并行状态”，不是“并发 session 的时间总和”。
```

## 推荐用户心智

用户最应该记住三句话：

```text
人工投入 = 指令 + 复盘 + 修复
AI 等待 = 可以被复用的窗口
并行时间 = 真实时钟里的重叠时间，不按 session 数翻倍
```

如果一个用户只看一个结论，应该看：

```text
今天我是在认真指挥 AI，还是在空等 AI，还是在替 AI 返工？
```
